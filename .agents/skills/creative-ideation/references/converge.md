# 收敛：收窄与决策

仅当发散耗尽、用户想收窄范围时加载——或说"决策""排序""选""做实"。技法库按设计是*发散*的（为生成而生）；这是刻意相反的阶段。把两者严格分开正是关键：绝不在想法还在流动时跑收敛，过早判断是杀死好想法的元凶。

**姿态保持。** 引导者模式中你基于*用户的裁决*跑收敛——你定结构、提问题，他们评判，绝不为他们排名。创意伙伴模式中你也参与。替我想模式中你自己收敛并展示结果，然后提议继续。

## 怎么跑

先把场地反射回去：把已生成的候选想法拉出来作为具体集合（包括奇怪的和埋着的，不只是最近显眼的），以便有东西可处理。然后选**一个**契合这个决策的收敛动作——不要给用户一张方法菜单；选适合*这个*决策的并命名它。跑到一个结果，在清晰的短名单或单一方向出现时停下。

按决策所需选择：

- **亲和聚类**——想法多而散时：分组为主题，命名每个簇，浮现贯穿线。常是正确的*第一步*，把一堆变成一把。
- **影响–投入**——目标是要行动时：把每个候选放在影响 vs 投入上；先收割高影响/低投入，其余搁置。
- **NUF 测试**——新颖性重要时：给每个评新颖（New）、有用（Useful）、可行（Feasible），各 1–10；总分暴露安静赢家与耀眼但注定失败的。
- **强制排名 / 点票**——只需一个有排名的 top-N 时：让想法竞争，不许并列。
- **PMI（加 / 减 / 有趣）**——一个强候选在承诺前需要压力测试时：列出它的 Plus、Minus、Interesting，然后评判。
- **MoSCoW**——为构建划范围时：分成 Must / Should / Could / Won't-this-time。

连串两三个收敛动作没问题（如聚类 → 给簇打分）；更多通常就是过度处理。

## 然后

短名单或方向一定，回到 `SKILL.md` 的"收尾"跑综合。

如果决策需要的不只是排序/聚类，而是冷水检验、第二视角重评、A/B/C 推荐或压力测试——把用户交给 `structured-decisions`，不要在这里做对抗式决策。
