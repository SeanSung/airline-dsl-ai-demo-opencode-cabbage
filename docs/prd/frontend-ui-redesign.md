# 前端 UI 全面重设计 — PRD

> 状态：Draft v1.0 · 2026-08-24
> 关联：产品 PRD `docs/prd/airline-dsl-edit-agent.md`（本 PRD 只重设计其前端表层，不变更产品功能/管线）
> Parent Issue（Flow Record）：#30 `frontend-ui-redesign`
> 本 PRD 只写意图（what/why），工程决策（目录结构、组件 API、token 命名、Tailwind/shadcn 接入细节）留给 flow-design。

---

## 1. Problem Statement

**谁**：航线编辑 Agent 的前端使用者——现场演示者、内部航线规划员，以及观看演示的领导/客户。

**什么问题**：
1. **没有 UI 设计**：前端所有样式为 inline `style={{}}`，无设计 token、无 CSS 框架、无组件库；配色仅一处硬编码深色（`#0b1220`/`#e2e8f0`），字体、间距、圆角、状态色全凭临时取值。
2. **UI 混乱**：布局为左栏固定 420px 内 ChatPanel 与 HistoryPanel 上下硬挤、右栏 RouteMap 满铺且 GBHSubmitBar 以浮层遮挡地图底部；信息层级不清、主次不分、操作反馈缺失。
3. **演示场景受损**：本产品的核心验收是"现场对话生成一条能飞的航线"，混乱的界面直接削弱"真实 AI 能力 + agent 原生"的说服力，与对外演示级目标不匹配。

**不解决的成本**：演示时界面无法支撑产品叙事；后续迭代直线/之字几何、更多动作、历史管理等界面时无统一基座，风格持续漂移、重复造轮子。

## 2. Thesis（why build it）

**为什么现在**：产品核心管线（对话→意图→几何→GBH 验证）已跑通，UI 成为演示质量的短板；在更多功能迭代前建立设计基座，成本最低、收益最久。

**为什么是重设计而非修补**：用户已明确判定现有界面在视觉、信息架构、交互流程三个层次都不达标（dm-101 全面重设计），inline-style 结构无保留价值；在零设计资产的现状上重做，比逐处修补更干净。

**差异化**：界面要成为"agent 原生 + 真实 3D 航线"叙事的一部分——三栏工作台让"历史·对话·地图"各司其职，深色主题与 Cesium 3D 地图融合为有科技感的驾驶舱，而非又一个表单后台。

## 3. Goals / Non-goals

**Goals**
- 建立统一的深色设计语言（design token + 主题化基础组件库），替换全部 inline style。
- 以"历史 · 对话 · 地图"三栏工作台重构信息架构，消除遮挡与硬挤。
- 让"生成→预览→微调→提交 GBH→看结果"全流程的状态反馈清晰、无歧义。
- 桌面大屏（1920×1080）达到对外演示级视觉；笔记本（1366×768）可用不碎。
- 沉淀可复用基座，支撑后续几何/动作/历史等界面迭代。

**Non-goals（本次明确不做）**
- ❌ 不变更任何产品功能、生成管线、API、数据模型（纯前端表层重设计）。
- ❌ 不做平板/手机响应式适配。
- ❌ 不产出独立设计规范文档或 Storybook 站点。
- ❌ 不做亮色主题（仅深色；token 预留主题能力但不实现切换）。
- ❌ 不做地图手动拖点编辑（沿用 PRD 非目标）。
- ❌ 不引入第二套 UI 库或 CSS-in-JS 方案。

## 4. 目标用户与场景

沿用产品 PRD：内部航线规划员/演示者为主要用户，最高频场景是**客户/领导面前演示沧海校区环绕巡检航线的对话式生成与 GBH 验证**。重设计必须优先服务"投影/大屏 + 旁观者观看"的演示语境——信息一眼可读、状态变化醒目、地图有视觉冲击。

## 5. 产品形态：三栏工作台

桌面大屏（≥1440px）下采用三栏布局，外加顶部应用条：

```
┌──────────────────────────────────────────────────────┐
│ 顶栏：产品标识 · 新对话 · 降级/连接状态 · 用户/设置入口    │
├───────┬──────────────────┬───────────────────────────┤
│ 历史   │  对话             │                           │
│ 会话   │  消息流（多轮澄清  │      Cesium 3D 地图        │
│ 列表   │  /流式/错误引导）  │   （航线预览主区域）        │
│       │                  │                           │
│ 续编/ │  输入框            │   航线参数卡 + GBH 提交/结果 │
│ 再提交│                  │                           │
└───────┴──────────────────┴───────────────────────────┘
```

- **左栏 历史**：会话/航线列表，支持加载续编、再次提交 GBH（迁移自原 HistoryPanel）。宽度较窄，以列表为主。
- **中栏 对话**：对话主区，承担多轮澄清、流式回复、错误引导、降级标注（迁移自原 ChatPanel）。
- **右栏 地图**：Cesium 3D 地图为右侧最大主区域；航线参数摘要与 GBH 提交/结果作为地图内的卡片/面板，**不得遮挡航线主体**（取代原底部遮挡式浮条）。

### 5.1 笔记本降级（1366×768）

历史栏默认收起为约 48px 的图标窄条，会话标题用 hover tooltip 显示；点击顶栏/图标栏「历史」按钮，历史以覆盖式抽屉展开。对话栏与地图栏保持并排，地图始终为右侧主区域。≥1440px 恢复三栏全展开。

### 5.2 交互流程要求（信息架构/反馈层）

- **生成中**：对话流式输出、地图/提交区有明确加载态，按钮禁用且有进度提示。
- **成功**：航线在地图高亮、参数卡显示结构化意图、GBH 提交结果（ok/invalid/error）状态醒目可辨。
- **失败/降级**：校验错误定位到字段并在对话中引导修正；LLM 不可用规则降级时，界面**显式标注"非 AI 生成"**（产品 PRD 硬要求）。
- **历史续编**：加载历史会话后对话与地图状态一致恢复，无数据丢失感。

## 6. 设计语言与技术选型

| 项 | 决策 |
|----|------|
| 样式方案 | **Tailwind CSS**（utility-first，替换 inline style） |
| 组件基础 | **shadcn/ui**（Radix 无样式原语 + 自研主题），按需 copy 组件源码进仓库 |
| 主题 | **自研深色主题 token**：颜色（背景/表面/边框/文本/主色/状态色）、字体、间距、圆角、阴影；默认深色，契合 Cesium 地图 |
| 状态色 | 统一 loading/success/error/warning 语义色，贯穿按钮、徽章、提交结果、降级标注 |
| 地图融合 | Cesium 容器与深色 UI 视觉一体（边缘/面板/浮层风格统一），避免"地图+白框"割裂感 |

> 品牌感强度（主色精确色值、字体家族、logo/命名）在 design 阶段确定；本 PRD 只锁定"深色 + 科技感 + 演示级"方向。

## 7. 设计系统沉淀范围

沉淀**可复用的设计基座**，不产出独立文档/Storybook：
1. **Design token**：颜色、字体、间距、圆角、阴影、状态色（CSS 变量 + Tailwind theme 映射）。
2. **主题化基础组件**：Button、Input/Textarea、Card、Dialog/Sheet（抽屉）、Tabs、Tooltip、Badge、ScrollArea、Toast/Sonner、Separator、Spinner 等 shadcn 组件的深色主题实例。
3. **布局骨架与业务通用组件**：三栏工作台骨架、顶栏、地图浮层卡片、对话气泡、状态徽章、GBH 提交条/结果卡——供后续几何/动作/历史界面直接复用。

## 8. 目标画布与响应式

| 断点 | 行为 |
|------|------|
| ≥1440px（最佳 1920×1080） | 三栏全展开，完整体验，演示级视觉 |
| 1366×768（笔记本下限） | 历史收起为图标栏+抽屉，对话/地图并排，不碎不遮，"能用"级 |
| <1366 | 不做适配/不承诺（平板、手机不在范围） |

Cesium 地图在所有受支持断点下始终为右侧主区域，不降级为小预览。

## 9. 验收标准（可判定）

> 每条均有可观察的 Pass 条件与判定方法；"好看"不可证伪，故拆为可检查的视觉/行为缺陷清单。断点：桌面 = 1920×1080 与 1366×768 两个分辨率下均须验证。

### 9.1 视觉一致性

**Pass 条件（全部满足）**
- 所有文字与背景对比度 ≥ WCAG 2.1 AA（正文 ≥4.5:1，大字/UI 组件 ≥3:1），可用浏览器对比度检查器量化。
- 无文字截断、无文字/图标重叠、无元素叠压（地图浮卡除外，其覆盖范围受 9.2 约束）。
- 颜色、字体、字号、间距、圆角、阴影全部引用 design token；`frontend/src/**/*.tsx` 中不出现硬编码颜色字面量（`#xxx`/`rgb()`/`rgba()`）——token 定义文件与第三方组件样式覆盖区除外。
- 同类组件视觉一致：所有按钮/输入/卡片/徽章在不同页面使用同一组件实例，无第二套配色或圆角。

**判定方法**：两个断点分别截图走查视觉缺陷清单 + 代码扫描硬编码颜色（0 处）+ 对比度抽查 ≥5 个关键文本节点。

### 9.2 布局无遮挡/无硬挤

**Pass 条件（全部满足）**
- 不出现整页横向滚动条：`document.documentElement.scrollWidth <= window.innerWidth`。
- 无内容被裁切不可达：任一栏内容超出时该栏内部出现纵向滚动，主体输入框（对话输入、GBH 提交按钮）在滚动时始终可见（sticky/固定）。
- 三栏互不重叠；1366 下历史收起为图标栏后，中栏对话气泡不与地图/抽屉重叠。
- 地图上的参数卡/GBH 结果面板覆盖 Cesium 画布面积 ≤ 25%，且不覆盖当前航线的航点主体（环绕圆/航点标记在未被遮挡的地图区域可见）。
- 抽屉/弹层（历史抽屉、Dialog）打开时遮罩不导致其后页面布局错位（无 reflow 跳动）。

**判定方法**：两个断点实测 + 对 `scrollWidth/innerWidth`、面板覆盖面积加自动化断言或手动测量；长会话/长历史列表下滚动验证输入区可见。

### 9.3 流程反馈完整（四态可观察）

**Pass 条件（四态逐一可见，非仅 console）**
- **生成中**：对话区有流式文本逐步输出；发送按钮处于 loading+disabled；生成完成前不可重复提交 GBH（按钮 disabled 且有 loading 指示）。
- **成功**：航线在地图高亮渲染；参数卡显示结构化意图（高度/速度/动作等非空字段）；GBH 提交成功有 success 状态色徽章并显示返回的 `gbhRouteId`。
- **失败**：校验/提交失败有 error 状态色提示，错误信息为人类可读文本（非原始 JSON/堆栈直接展示）；对话中可定位到问题字段并引导修正；提供可重试入口。
- **降级**：LLM 不可用走规则兜底时，界面显示明确的"非 AI 生成"警告徽章/横幅（产品 PRD 硬要求），不能与成功态外观混淆。

**判定方法**：四态逐一手动触发走查（成功、构造校验失败、断网/后端 500、关闭 LLM Key 触发降级）+ 现有 `*.test.tsx` 及新增断言验证反馈元素在对应状态下存在于 DOM。

### 9.4 inline style 清零

**Pass 条件**
- `frontend/src/**/*.tsx` 中 JSX `style={{ ... }}` 属性出现次数 = 0。
- 白名单（允许保留，需逐处注释说明）：Cesium 命令式 API 传入的纯样式对象（如 `cesium-entities.ts` 中 `new Entity({ ... })` 的图形属性）、以及确实无法用 CSS 表达的运行时动态尺寸（如 Cesium container 的像素尺寸）。
- 禁止用 `style={{}}` 承载颜色/间距/字体/圆角/阴影等主题值——这些必须走 Tailwind class 或 token。

**判定方法**：对 `frontend/src` 执行正则扫描 `<[A-Za-z]+[^>]*\bstyle=\{\{` 计数为 0（白名单逐行核对）；CI 可加 ESLint 规则 `react/no-object-inline-style` 或等价约束防止回归。

### 9.5 设计基座可复用

**Pass 条件**
- 存在单一 token 真相源：颜色/间距/字体/圆角/阴影在一处定义（CSS 变量 + Tailwind theme 映射），全局引用，无重复定义。
- 基础组件集中于 `frontend/src/components/ui/`（Button/Input/Textarea/Card/Badge/Tabs/Dialog/Sheet/Tooltip/ScrollArea/Toast 等），业务组件只从此处 import，不自行实现同类基础控件。
- 主题切换能力由 token 层承载（即使 MVP 不实现亮色，也无硬编码颜色散落在业务组件中，使加主题不需改业务代码）。
- 后续新增一个几何模板/动作界面时，不需要新增任何颜色/间距 token 之外的视觉常量、不新建第二套按钮/卡片样式。

**判定方法**：目录结构检查（components/ui 存在且被业务组件 import）+ 代码扫描（硬编码颜色/间距字面量在 `components/ui` 与 token 文件之外为 0）+ 以"新增一个直线模板界面"为假设走查是否需要新基础组件。

## 10. 技术约束（供 flow-design）

- 前端栈不变：React 19 + Vite + TypeScript + 原生 Cesium。
- 新增依赖仅限：`tailwindcss`、`shadcn/ui` 及其 Radix 依赖、`class-variance-authority`、`clsx`/`tailwind-merge` 等 shadcn 标配工具链；不得引入第二套 UI 库。
- 现有组件（ChatPanel/HistoryPanel/RouteMap/GBHSubmitBar/chatReducer/useChatStream）的**功能契约与 props 语义保持不变**，重构样式与布局即可；现有测试（`*.test.tsx`）需继续通过。
- 天地图 token 仍由服务端下发，不得在前端硬编码（沿用产品 PRD）。
- Node ≥22.19，npm workspaces（shared/server/frontend）结构不变。

## 11. 演示验收（Door check）

在 1920×1080 投影下：对话生成沧海校区环绕线 → 三栏界面中对话流式输出、地图高亮航线、参数卡可读 → 一键提交 GBH → 结果状态醒目；整个过程界面无遮挡、无 inline-style 痕迹、深色主题与 3D 地图一体，达到"对外演示级"。
